# 08. GM学習ループ（Step 4〜5 の仕様）

> **本書は Step 4〜5 のための仕様であり、Step 1 では実装しない。**
> Step 1 で表示する「GM学習状況」パネル（Tab3）は**ダミー値**であり、画面上にその旨を明示する。

---

## 1. GM（ゲームマスター）とは

クエストの**査定**と**デイリー生成**を担う AI エージェント。Step 4 で導入する。

| 責務 | 内容 |
|---|---|
| 査定 | 完了したクエストの **難易度(D1〜D5) / 新規性 / 完遂度** を判定し、EXP を算出する（`04_exp_rules.md` の式をそのまま使う） |
| デイリー生成 | 毎週月曜朝に、その週のデイリー5個を確定する（`05_quest_design.md` §2.2） |
| 通知 | **Discord Webhook** で結果を通知する |

> **ルール**: GM は `src/lib/exp.ts` / `penalty.ts` / `level.ts` を**そのまま呼ぶ**。
> GM 側に計算式を再実装しない（式が2箇所に分裂すると数値がズレるため）。
> これが Step 1 の時点で `exp.ts` / `penalty.ts` を先に実装しておく理由。

## 2. Step 5 の学習ループ（確定している構成要素）

プランで挙がっている5要素。**各要素の詳細設計は未確定。**

| 要素 | 目的 |
|---|---|
| **rubric（ルーブリック）** | 査定基準を条項として蓄積する。判定のブレを減らす |
| **calibration（較正）** | GM の見積と実績の乖離を測り、判定を補正する |
| **golden set** | 正解付きの査定サンプル集。GM の精度を測る基準データ |
| **異議申し立て** | 本人が査定に異議を出し、結果と理由を rubric に反映する |
| **リグレッションテスト** | rubric 更新後に golden set を再評価し、**過去の正しい判定が壊れていないか**を確認する |

```
  クエスト完了
      │
      ▼
  ┌─────────┐   異議申し立て   ┌──────────┐
  │  GM査定  │ ───────────→ │  rubric  │
  └─────────┘                └──────────┘
      │                            │ 更新
      ▼                            ▼
  ┌─────────┐              ┌──────────────┐
  │  EXP付与 │              │ golden set で │
  └─────────┘              │ リグレッション │
      │                     └──────────────┘
      ▼                            │
  calibration ←────────────────────┘
  （見積 vs 実績の乖離を測定）
```

## 3. Tab3「GM学習状況」パネルの表示項目

Step 1 は**ダミー値**。Step 5 で実データ化する。

| 指標 | 意味 | Step 1 |
|---|---|---|
| 見積精度の推移 | GM の EXP 見積と実績の乖離（時系列） | ダミー |
| D判定一致率 | 難易度判定が本人の感覚と一致した割合 | ダミー |
| ルーブリック条項数 | 蓄積された査定ルールの数 | ダミー |

> **ルール**: Step 1 の画面には `Step 5 で実データ化` のラベルを必ず添える
> （ダミー値を実データと誤認させない）。
