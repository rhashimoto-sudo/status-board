# 05. クエスト設計（4階層）

> クエストは EXP の唯一の入口。階層ごとに周期・EXPレンジ・失敗時のコストが異なる。
> 失敗時のペナルティ詳細は `06_penalty.md`。

---

## 1. 4階層の概要

| 階層 | 周期 | EXPレンジ | 個数 | 失敗時 |
|---|---|---|---|---|
| 🗓 **デイリー** | 毎日 | 5〜15 | **固定5個** | HP −10 / EXECUTION −10 / ストリーク0 |
| ⚡ **ゲリラ** | 突発 | 20〜80 | 不定 | HP −25 / 主ステ −(基礎値×50%) / BRIDGE −20 |
| 📜 **ミッション** | 週〜月 | 200〜500 | 1〜3並行 | HP −40 / EXECUTION −(予定EXP×30%) |
| 👹 **ボス** | 月〜四半期 | 400〜1500 | 1体 | HP −50 / 敗北デバフ7日 / 💀敗北ログ |

```
     周期短い ────────────────────────────→ 周期長い
     報酬小                                   報酬大
  ┌──────────┐ ┌────────┐ ┌──────────┐ ┌────────┐
  │ 🗓デイリー │ │ ⚡ゲリラ │ │📜ミッション│ │ 👹ボス  │
  │  5〜15    │ │ 20〜80  │ │ 200〜500 │ │400〜1500│
  │ 毎日固定5 │ │  突発   │ │  週〜月   │ │月〜四半期│
  └──────────┘ └────────┘ └──────────┘ └────────┘
     習慣の維持    割り込み耐性   計画遂行力     到達目標
```

## 2. 🗓 デイリークエスト

### 2.1 仕様

| 項目 | 内容 |
|---|---|
| 個数 | **毎日固定5個**（増減しない） |
| うち探索枠 | **必ず1個**（§2.4） |
| EXP | 1個あたり 5〜15（探索枠は新規性が高く出るため上振れする） |
| ストリーク | **5個すべて達成した日のみ**維持。1個でも欠けたら **0 にリセット** |
| 回復 | 全達成で HP **+5 / 日** |
| 入れ替え | **週単位のみ**。**月曜朝に確定し、週中はロック** |

> **ルール**: ストリークは「部分達成」を認めない。4/5 でも 0 にリセットされる。
> これは「毎日必ず全部やる」という一点だけを習慣化の対象にするため。
> UI では**あと何個で途切れるか**を常に強調表示する（`09_dashboard_spec.md`）。

### 2.2 週次ロックの理由と挙動

| 状態 | 挙動 |
|---|---|
| 月曜朝 | その週の5個を確定する。この時だけ変更できる |
| 火〜日 | 🔒 **ロック**。内容を変更できない。UI に「次に選び直せる日」を明示する |

> **設計意図**: 気分でデイリーを差し替えられると、難しいものが永久に後回しになる。
> 週単位で固定することで「今週はこれをやると決めた」というコミットメントを強制する。

### 2.3 現行の5個（2026-08-15 本人確定）

| # | 内容 | 主ステータス | EXP | |
|---|---|---|---|---|
| 1 | まだ触ったことのない技術・分野に30分触れる（成果は問わない） | 💻 TECH | 25 | **探索枠** |
| 2 | 朝30分以上で開発や思考整理をする | 🧠 INT | 15 | |
| 3 | ベッドにいる時と朝にスマホを触らない | **なし** | **0** | 土台 |
| 4 | 朝6時に起きる | **なし** | **0** | 土台 |
| 5 | 朝15分のランニングをする | **なし** | **0** | 土台 |

実体は Notion の Quests DB。`src/data/quests.json` は静的な初期表示用の写し
（`10_notion_schema.md` §5）。両者を同じ内容に保つこと。

### 2.3.1 生活基盤のデイリーは軸を持たない

3〜5 は睡眠・運動・スマホ断ちで、**能力ではなく生活の土台**である。
**9軸はすべて能力軸なので、どこに入れても嘘になる。**

> **ルール**: 生活基盤のデイリーに `main` を割り当ててはならない。
> 割り当てると「早起きしただけでレーダーの該当軸が伸びる」ことになり、**形が意味を失う**。
> 型は `DailyQuest.main: MainStatusKey | null`。UI は EXP の代わりに「土台 → ⚔️」と表示する。

**EXP 0 でも機能は落ちない。** デイリーの本体は EXP ではなく**ストリーク**であり
（§2.1「部分達成を認めない」）、⚔️EXECUTION は完了・ストリーク・期限内達成から
**自動導出**される（`03_status_system.md` §1.1）。
「早起きすべきと知っている。問題はやるかどうか」は EXECUTION の定義そのもので、
軸を割り当てなくてもストリーク経由で正しく効く。

デイリーの EXP は 5〜15 で、仕事タスク（25〜400）に比べれば誤差でもある。

> **注意**: `src/lib/notion.ts` の `toDailyQuest` は以前 `MainStatus` 未設定を
> `?? "TECH"` で既定値に寄せていた。**早起き・運動が黙って TECH に化けていた。**
> 既定の軸に寄せる実装を再び入れないこと（回帰テストで固定済み）。

### 2.3.2 🌎ENGLISH の供給源について

旧 #3「英語の技術文書を10分読む」が `00_profile.md` §4.1 の
**(c) 英語の一次情報を読む**の実装だった。上記の差し替えでこれが無くなり、
**ENGLISH はデイリーからも仕事（`10_notion_schema.md` §7.1 に ENGLISH は現れない）からも
入らなくなった。**

> **本人確定（2026-08-15）**: **(ア) ENGLISH は 0 のまま受け入れる。**
> §4.1 の (a)「低さを自分で許容する」の立場を採る。TOTAL Lv は全9平均を 0.4 の重みで
> 含むため、じわじわ効き続けることを承知の上での判断。
> `navigator` はこれを弱点として指摘しないこと（`00_profile.md` §7.2 の禁じ手）。

### 2.4 探索枠（毎日1個は必ず未知に触れる）

`00_profile.md` §6.4 に基づく。**🔥好奇心・探索 は本人の長期の起爆剤**である一方、
合格条件（`00_profile.md` §3）から逆算したクエストは**すべて既知の課題**になりがちで、
放っておくと探索が締め出される。**枠として確保する。**

| 項目 | 内容 |
|---|---|
| 個数 | `DAILY_EXPLORATION_SLOT_COUNT` = **1**。0 にしてはならない |
| 完了条件 | **未知に触れたこと自体**。成果を問わない |
| 型 | `DailyQuest.exploration: boolean` |
| EXP | 新規性が `first` になるため上振れする。結果 🔥LEARNING に自然に効く |

> **ルール**: `quest-designer` は毎週この枠を必ず 1 個満たす。
> UI は探索枠を**他の4個と区別して表示する**（`daily-quests.tsx`）。
> 区別が付かないと「成果が出せなかった」と誤認され、探索枠の意味が消えるため。

## 3. ⚡ ゲリラクエスト

| 項目 | 内容 |
|---|---|
| 発生 | 突発。予定外の割り込み（依頼・障害・急な相談） |
| EXP | 20〜80 |
| 期限 | 短い（数時間〜数日） |
| 失敗 | HP −25 / 主ステータス −(基礎値×50%) / 🤝BRIDGE **−20** |

> **ルール**: ゲリラの失敗だけが 🤝BRIDGE に直接ダメージを与える。
> **他者を待たせた**という事実に対するペナルティであり、「橋渡し」能力の毀損として表現する。

- 🚨緊急ボードに**ボスと並べて最上部**に表示する
- **秒まで動くカウントダウン**を出し、残り3日未満で赤く発光させる

| 項目 | 内容 |
|---|---|
| 周期 | 週〜月 |
| EXP | 200〜500 |
| 構造 | **子クエストを持つ**。進捗バーで達成率を表示する |
| 成功 | HP **+20** |
| 失敗 | HP −40 / ⚔️EXECUTION −(予定EXP × 30%) |

## 6. ステータス配分ルール（全階層共通）

| ルール | 内容 |
|---|---|
| 加算先 | **主ステータス1つ + 副ステータス最大1つ**。副は 50% 換算 |
| 構造化 | 関与ステータスが **3つ以上**なら《構造化》発動 + 構造化ボーナス |
| 🤝BRIDGE | **他者が絡むタスクにのみ**設定できる |
| 🔥/⚔️ | **手入力不可**。新規性・完遂実績から自動導出（`04_exp_rules.md` §3） |
| 証拠 | 無ければ **EXP 0** |

## 7. 💀 敗北ログ

失敗した ボス / ゲリラ / ミッション の**墓標**。Tab2 の最下部に置く。

| 記録項目 | 内容 |
|---|---|
| 種別 | 👹ボス / ⚡ゲリラ / 📜ミッション |
| 名称 | 失敗した対象の名前 |
| 日付 | 失敗した日 |
| 被ダメージ | 失った HP と EXP の内訳 |
| リベンジ対象 | 再挑戦可能かどうか（ボスは常に可） |

Step 1 ダミーは **2件**（討伐失敗ボス1 + 失敗ミッション1）。

## 8. 測定期間中の扱い（CALIBRATION PHASE）

| 項目 | 通常 | 測定期間中（14日間） |
|---|---|---|
| クエスト | 4階層すべて | **9ステータス × 各2件 = 18件**の測定用クエスト |
| ペナルティ | 適用 | **完全免除**（HP減少なし・GAME OVERなし） |
| ストリーク | 維持/リセット | **記録のみ**（途切れてもペナルティなし） |
| 目的 | EXPを稼ぐ | **初期Lvを実測する** |

初期Lv算出: `clamp(1..5, round(自己申告点 × 0.4 + 実測点 × 0.6))`

測定する値: 実測時間 / 標準時間の比、完遂率、初挑戦タスクの突破速度、自己申告の経歴

終了時に「覚醒」演出 → 初期ステータス確定 → 固有スキル解放 → 本編開始。

> **未確定**: 18クエストの具体的な中身は Step 3 で GM と一緒に組む（`01_requirements.md` §10）。
