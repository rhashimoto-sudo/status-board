# 06. ペナルティ設計（HP制・EXP減点・GAME OVER）

> 失敗のコストを **HPゲージ** と **EXP直接減点** の両方で表現する。
> 数値はすべて `src/lib/constants.ts`、ロジックは `src/lib/penalty.ts` に置く。

---

## 1. 設計方針

| 方針 | 理由 |
|---|---|
| 失敗を1つの HP ゲージに集約する | 危うさが一目で分かり、「立て直す」体験が生まれる |
| EXP も同時に削る | HPだけだと「HPさえ持てばサボれる」抜け道ができる |
| ただし Lv・称号は下げない | 積み上げた実績が消えると復帰意欲が折れる |
| HP 0 だけは全初期化する | 唯一の本当の失敗を1つだけ用意し、緊張感を担保する |
| 殿堂に記録は永久保存する | 全部消えると「もう見たくない」で離脱するため、記録だけは残す |

---

## 2. ペナルティ表

| 失敗 | HP | EXP減点 | 追加効果 |
|---|---|---|---|
| 🗓 **デイリー未達**（5個のうち1つでも） | **−10** | ⚔️EXECUTION **−10** | 🔥ストリーク **0** にリセット |
| 🗓 **デイリー3日連続未達** | **−10/日** | 同上 | 🔻**衰弱**: 全EXP獲得 ×0.8（**3日間**） |
| ⚡ **ゲリラ期限切れ** | **−25** | 主ステータス **−(基礎値 × 50%)**、🤝BRIDGE **−20** | 他者を待たせた扱い |
| 📜 **ミッション失敗** | **−40** | ⚔️EXECUTION **−(予定EXP × 30%)** | — |
| 👹 **ボス討伐失敗** | **−50** | 獲得 **0**（減点はしない） | 💀敗北ログに記録、🔻**敗北**: 全EXP ×0.9（**7日間**） |

### 2.1 回復

| 行動 | HP |
|---|---|
| 🗓 デイリー**全達成**（5/5） | **+5 / 日** |
| 📜 ミッション完遂 | **+20** |
| 👹 ボス討伐成功 | **+50** |

> **ルール**: HP は **0..100 でクランプ**する。回復で 100 を超えず、減少で 0 を下回らない
> （0 を下回る計算結果になった場合は 0 に丸めた上で GAME OVER を発火する）。

---

## 3. デバフ

| デバフ | 倍率 | 期間 | 発生条件 |
|---|---|---|---|
| 🔻 衰弱 | ×0.8 | 3日 | デイリー3日連続未達 |
| 🔻 敗北 | ×0.9 | 7日 | ボス討伐失敗 |
| 🔻 戦闘不能 | ×0.5 | 3日 | HP が 10 未満の状態（瀕死） |

> **ルール**: **デバフは重複しない。** 複数成立している場合は**最も重い（倍率が最小の）1つのみ**を適用する。
> 例: 衰弱(0.8) + 敗北(0.9) が同時 → **0.8 のみ**。乗算して 0.72 にはしない。
> UI では成立中のデバフを全てバッジ表示してよいが、**計算に効くのは1つだけ**であることを明示する。

デバフの重さの順序（重い順）: `戦闘不能(0.5) > 衰弱(0.8) > 敗北(0.9)`

## 4. 安全装置

| # | 装置 | 内容 |
|---|---|---|
| S-1 | **EXPフロア** | EXP減点は `floorExp()` を通す。**現Lvの下限累積EXPを下回らせない** → Lv・称号は下がらない |
| S-2 | **HPクランプ** | HP は常に `0 <= hp <= 100` |
| S-3 | **デバフ非重複** | 最も重い1つのみ適用 |
| S-4 | **測定期間の免除** | `phase === "calibration"` の間は**ペナルティを一切適用しない**（HP減少なし・GAME OVERなし） |

```ts
// 概念
function applyPenalty(kind: PenaltyKind, state: GameState): PenaltyResult {
  if (state.phase === "calibration") return NO_PENALTY; // S-4
  // ... hpDelta / expDeltas / debuff を算出
}
```

> **注意**: S-4 の免除判定は**ペナルティ適用の最初**に行う。
> 個々のペナルティ種別ごとに免除を書くと漏れるため、入口で1箇所に集約すること。

## 5. ☠ GAME OVER（HP 0）

HP が 0 に到達した時点で発火する。

### 5.1 初期化される（消える）もの

- 全9ステータスの**累積EXP → 0**
- **Lv → 1**、**称号 → Lv1 の称号**
- 実績・進行中クエストの進捗
- 🔥ストリーク → 0
- 固有スキル《構造化》の**発動回数 → 0**、派生の解放 → 全て未解放

### 5.2 殿堂（Hall of Fame）に永久保存されるもの

| 項目 | 内容 |
|---|---|
| generation | その周回の番号 |
| 最高到達 TOTAL Lv | 周回中の最大値 |
| ステータス別の最高到達Lv | 9件 |
| 獲得した称号 | 到達した最高称号 |
| 討伐したボス | ボス名と討伐日 |
| 最長ストリーク | 日数 |
| 生存日数 | 開始日から GAME OVER までの日数 |
| 終焉日 | GAME OVER の日付 |

### 5.3 手順

```
gameOver(state):
  1. 現在の記録を HallOfFameEntry にスナップショットする
  2. hallOfFame.entries に push する（既存エントリは絶対に消さない）
  3. 全ステータス・Lv・称号・実績・ストリーク・固有スキルを初期化する
  4. HP を 100 に戻す
  5. generation を +1 する
  6. phase は "main" のまま（測定期間には戻らない）
```

> **ルール**: 殿堂は**追記のみ**。GAME OVER のたびにエントリが1件増える。
> 初期化処理が殿堂に触れて内容を消すことがあってはならない。

## 6. HP 収支の見通し（緊張感の妥当性確認）

未達 −10 / 全達成 +5 のため、**均衡には「全達成:未達 = 2:1」が必要**。

| ペース | 週のHP収支 | GAME OVER まで |
|---|---|---|
| 週2日落とす | +5 | 到達しない |
| 週3日落とす | −10 | 約10週 |
| 週4日落とす | −25 | 約4週 |

GM 設計の目標達成率 70% とほぼ一致する水準。

> **注意**: この収支は**デイリーのみ**を考慮した概算。ゲリラ・ミッション・ボスの失敗が重なると
> 急速に悪化する。緩めたくなった場合は `constants.ts` の `HP_PENALTY` / `HP_RECOVERY` を1箇所変えれば済む。

## 7. HP のUI表現

正典は `01_requirements.md` FR-8-1。閾値は `constants.ts` の `HP_COLOR_THRESHOLDS` に置く。

| HP帯 | 色 | 表現 |
|---|---|---|
| **51〜100**（`hp > 50`） | 緑 | 通常 |
| **26〜50**（`hp > 25`） | 黄 | 注意 |
| **0〜25**（`hp <= 25`） | 赤 | **危険域。発光あり** + テキストラベル併記 |
| 0〜9（瀕死） | 赤 | 上記に加えて 🔻戦闘不能バッジ |
| 測定期間中 | グレー | 数値ではなく **`—`** を表示し「ペナルティ免除中」と併記 |

> **要確認（仕様の食い違い）**: `01_requirements.md` FR-9 に「HP 62/100（… → **黄色域**）」とあるが、
> FR-8-1 の閾値（緑は `hp > 50`）では **62 は緑域**になる。本書は **FR-8-1 の閾値を正**とし、
> ダミーの HP 62 は**緑域**として描画する。
> 「62 を黄色にしたい」場合は閾値側（例: 緑 `hp > 70`）を変更する必要があるため、ユーザー確認事項とする。

> **ルール**: 色だけで危険を伝えない（NFR-6）。危険域では**テキストラベルも併記**する。
> 発光は `prefers-reduced-motion` 時に抑制する。

## 8. 検証項目（受け入れ条件）

| # | 項目 | 期待 |
|---|---|---|
| P-1 | HPクランプ下限 | HP 5 の状態で −25 → **0**（−20 にならない）かつ GAME OVER が発火 |
| P-2 | HPクランプ上限 | HP 98 の状態で +50 → **100**（148 にならない） |
| P-3 | EXPフロア | Lv5（下限926）・累積940 の状態で −50 → 累積 **926**、Lv **5**、称号不変 |
| P-4 | EXP下限 | Lv1・累積5 で −10 → 累積 **0**（負にならない） |
| P-5 | デバフ非重複 | 衰弱と敗北が同時成立 → 適用倍率は **0.8** のみ（0.72 にならない） |
| P-6 | 測定期間免除 | `phase === "calibration"` で任意のペナルティを適用 → HP 変化 **0**、GAME OVER 発火**なし** |
| P-7 | GAME OVER | HP 0 到達で全ステータス初期化・HP 100・`generation` +1 |
| P-8 | 殿堂の保全 | GAME OVER 後、殿堂に**新しいエントリが1件増え、既存エントリが消えていない** |
| P-9 | ストリーク | デイリー 4/5 達成 → ストリーク **0**（維持されない） |
| P-10 | ゲリラ期限切れ | HP −25 かつ 主ステ −(基礎値×0.5) かつ BRIDGE −20 が同時に適用される |
