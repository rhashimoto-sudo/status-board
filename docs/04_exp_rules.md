# 04. EXP計算ルール・レベル曲線

> 本書は EXP とレベルに関する**唯一の正典**。数値はすべて `src/lib/constants.ts` に定義し、
> ロジック（`src/lib/exp.ts` / `src/lib/level.ts`）はそこから読む。コード内に数値を直書きしない。

---

## 1. EXP 計算式

```
EXP = 基礎値(difficulty)
      × 新規性倍率(novelty)
      × 完遂度(completion)
      × 構造化ボーナス(structureMultiplier)
      × デバフ倍率(debuffMultiplier)
```

小数第1位で四捨五入して整数に丸める（`Math.round`）。

### 1.1 基礎値（難易度 D1〜D5）

| 難易度 | 基礎値 | 目安 |
|---|---|---|
| D1 | 10 | 15分程度で終わる定型作業 |
| D2 | 25 | 1時間程度。手順は分かっている |
| D3 | 60 | 半日。調べながら進める必要がある |
| D4 | 150 | 数日。設計判断を伴う |
| D5 | 400 | 数週間。前例がなく、成果物が外部に出る |

### 1.2 新規性倍率

| 区分 | 倍率 | 判定 |
|---|---|---|
| 初挑戦 | **1.5** | その領域で初めて取り組む |
| 2〜5回目 | **1.0** | 慣れてきたが定型ではない |
| 習熟 | **0.5** | 6回目以降。もう学びが少ない |

> **ルール**: 🔥LEARNING の伸びはこの新規性の高いタスクからしか生まれない。
> 同じことを繰り返しても LEARNING は伸びない設計であること。

### 1.3 完遂度

`0.0 〜 1.0` の実数。GM（Step 4 以降）が成果物を見て判定する。Step 1 ではダミー値。

| 完遂度 | 状態 |
|---|---|
| 1.0 | 要求を完全に満たした |
| 0.7 | 主要部分は達成。細部が未完 |
| 0.4 | 着手して形にはなったが目的未達 |
| 0.0 | 未着手と同等 |

### 1.4 構造化ボーナス

**3ステータス以上にまたがるタスクのみ**に適用する。倍率は固有スキル《構造化》の Lv に連動（1.15〜1.50）。
詳細は `07_unique_skill.md`。**2ステータス以下のタスクでは 1.0（ボーナスなし）**。

### 1.5 デバフ倍率

| デバフ | 倍率 | 期間 |
|---|---|---|
| 🔻衰弱 | ×0.8 | 3日 |
| 🔻敗北 | ×0.9 | 7日 |
| 🔻戦闘不能 | ×0.5 | 別途定義（`06_penalty.md`） |

> **ルール**: デバフは**重複しない**。同時に複数成立している場合は**最も重い（倍率が最小の）1つのみ**を適用する。
> 例: 衰弱(0.8) と 敗北(0.9) が同時なら **0.8 のみ**を掛ける（0.72 にはしない）。

## 2. ステータスへの配分

| ルール | 内容 |
|---|---|
| 主ステータス | 1タスクにつき**必ず1つ**。算出した EXP を **100%** 加算する |
| 副ステータス | 1タスクにつき**最大1つ**（0でもよい）。算出した EXP を **50%** 加算する |
| 上限 | 主1 + 副1 の**合計2つまで**。3つ以上のステータスに直接加算はしない |

> **注意**: 「3ステータス以上にまたがる」は**構造化ボーナスの発動条件**であり、
> **EXPの加算先が3つになるという意味ではない**。加算先は常に主1＋副最大1に絞る
> （分散させると1本あたりの伸びが薄まり、レーダーに形が出なくなるため）。

### 2.1 加算対象外・特則

| 対象 | ルール |
|---|---|
| 証拠なし | **EXP 0**。URL・スクリーンショット・成果物ファイルのいずれも無い場合は加算しない |
| 🤝BRIDGE | **他者が絡むタスクにのみ**加算できる。1人で完結した作業には入れない |
| 🔥LEARNING / ⚔️EXECUTION | **主・副として手入力しない**（下記 3 で自動導出する） |

## 3. 🔥LEARNING / ⚔️EXECUTION の自動導出

この2つは専門7ステータスの活動の**副産物**であり、直接指定できない。

| ステータス | 導出元 |
|---|---|
| 🔥 LEARNING | そのタスクの**新規性ぶん**。新規性倍率が 1.5（初挑戦）のとき算出EXPの一定割合、1.0 のとき小さく、0.5（習熟）のとき 0 |
| ⚔️ EXECUTION | **完了・ストリーク維持・期限内達成**から加算。期限を守って終わらせた事実そのものに対して与える |

> **ルール**: この設計により「学んでいるが動いていない」「動いているが学んでいない」の
> どちらの偏りも**歪みメーター**（Tab1）に必ず現れる。手入力を許すとこの検知が壊れるため、
> UI・API のいずれからも LEARNING / EXECUTION の直接指定を受け付けてはならない。

## 4. レベル曲線

初期100・公比1.6の指数カーブを Lv1-10 の10段で定義し、公比 `1.6^(1/10)` の等比補間で
Lv1-100 の100段に再分割する（Issue #25 で100段化）。10段ごとに旧10段設計の閾値へ厳密一致させる。
**次のLvに上がるために必要な累積EXP**の閾値テーブル（抜粋。全100段は `LEVEL_THRESHOLDS` が正典）:

| Lv | 到達に必要な累積EXP |
|---|---|
| 1 | 0 |
| 10 | 88 |
| 20 | 240 |
| 30 | 485 |
| 40 | 876 |
| 50 | **1501**（初期 levelCap） |
| 60 | 2502 |
| 70 | **4103**（ゲート①解放後の上限） |
| 80 | 6663 |
| 90 | **10761**（ゲート②解放後の上限） |
| 91 | 11287（旧10段設計のカンスト地点） |
| 100 | **17318**（ゲート③解放後の上限。MAX_LEVEL） |

```ts
// src/lib/constants.ts（抜粋。全100要素は constants.ts を参照）
export const LEVEL_THRESHOLDS = [/* Lv1..Lv100 の100要素 */] as const;
export const MAX_LEVEL = 100;
```

### 4.1 Lv 判定の仕様（levelCap非適用の生Lv）

- `levelFromExp(exp, levelCap = MAX_LEVEL)` は、**`exp >= 閾値` を満たす最大の Lv** を `levelCap` で
  クランプして返す。`levelCap` 省略時（既定値 `MAX_LEVEL`）はキャップなしと数学的に等価（no-op）で、
  この場合に返る値が**生Lv**である
- 境界値は**閾値ちょうどで上のLvになる**（`>=`）

| 累積EXP | 生Lv | 理由 |
|---|---|---|
| 0 | 1 | 開始値 |
| 87 | 9 | Lv10の閾値88未満 |
| 88 | **10** | 閾値ちょうどはLvアップ |
| 925 | **40** | Lv41の閾値926未満 |
| 926 | **41** | 閾値ちょうど |
| 11286 | **90** | Lv91の閾値11287未満 |
| 11287 | **91** | 閾値ちょうど（旧設計のカンスト地点） |
| 17318 | **100** | 閾値ちょうど。以降 MAX |
| 999999 | 100 | Lv100 が上限。それ以上は上がらない |

### 4.2 次Lvまでの残EXP

```
残EXP = LEVEL_THRESHOLDS[currentLv] - currentExp     // currentLv < 100
進捗率 = (currentExp - LEVEL_THRESHOLDS[currentLv-1])
        / (LEVEL_THRESHOLDS[currentLv] - LEVEL_THRESHOLDS[currentLv-1])
```

Lv100（MAX）のときは残EXPを算出せず、UI 上は `MAX` と表示し進捗バーを満杯にする。
`expToNextLevel` / `levelProgress` は **levelCap を引数に取らない**（生の累積EXPに対する値を
返し続け、levelCap 到達中も「貯まっているEXP量」がそのまま見える。S-2 の要件）。

### 4.3 levelCap（全軸共通の単一キャップ）

- **実効Lv = `min(生Lv, levelCap)`**。全9軸に共通の単一キャップであり、ボス1体の討伐で
  9軸すべてが同時に解放される
- 初期値は **Lv50**（`INITIAL_LEVEL_CAP`。測定期間の初期Lv上限と一致）
- ゲートボス討伐で `LEVEL_CAP_GATES = [50, 70, 90, 100]` の順に解放される（対応する合格条件は
  `00_profile.md` §3。`01_requirements.md` FR-2-2 が正典）
- **称号・派生スキル・TOTAL Lv・最終クラス判定はすべて実効Lvを使う。** EXPフロア（§6）だけは
  例外で、**生Lvを基準**にする

## 5. TOTAL Lv

尖り（得意分野）と穴のなさ（弱点の少なさ）を**両方**評価する。

```
TOTAL = 上位5ステータスの実効Lv平均 × 0.6 + 全9ステータスの実効Lv平均 × 0.4
```

- 「上位5」は**9ステータスの実効Lvを降順ソートした先頭5件**
- 結果は小数第1位まで保持し、表示は小数第1位まで（例: `Lv 42.3`）
- 総合称号は TOTAL Lv を**切り捨てた整数**を10刻みの帯に丸めて対応させる（`03_status_system.md`）

> **設計意図**: 平均だけだと1本の突出で全体が上がってしまい、弱点を隠せてしまう。
> 逆に最小値だけを見ると尖りが評価されない。0.6:0.4 の配合で
> **「1つ強いだけでは上がりきらず、全部そこそこでも上がりきらない」**状態を作る。

## 6. EXP フロア（安全装置）

ペナルティによる EXP 減点で **Lv・称号が下がってはならない**。基準は**生Lv**（levelCap非適用）である。

```
floorExp(newExp, currentRawLv) = max(newExp, LEVEL_THRESHOLDS[currentRawLv - 1])
```

- 減点後の累積EXPが**現在の生Lvの下限閾値を下回る場合、下限で止める**
- したがって日々のペナルティで Lv が下がることは**ない**
- Lv が下がるのは **GAME OVER 時のみ**（全初期化）
- **基準を実効Lv（levelCap適用後）にしてはならない。** levelCap 到達中に貯めた EXP が減点の
  たびに実効Lvの下限まで削られ、S-2 の「キャップ中もEXPは貯まり続ける」が壊れる
  （`src/test/exp.test.ts`「applyExpDelta と levelCap（S-2 の不変条件）」で固定されている）

| 例 | 減点前 | 減点 | 素の結果 | フロア後 | 生Lv |
|---|---|---|---|---|---|
| 生Lv41（下限926）で −50 | 940 | −50 | 890 | **926** | 41（不変） |
| 生Lv41（下限926）で −10 | 1000 | −10 | 990 | 990 | 41（不変） |
| 生Lv1（下限0）で −10 | 5 | −10 | −5 | **0** | 1（不変） |

> **ルール**: 累積EXPは**負の値にならない**（Lv1 の下限 0 でフロアされる）。

## 7. 計算例

### 例1: 初挑戦の中規模タスク（構造化あり）

| 項目 | 値 |
|---|---|
| 難易度 | D3（基礎値 60） |
| 新規性 | 初挑戦（1.5） |
| 完遂度 | 1.0 |
| 構造化 | 3ステータスに跨る。《構造化》Lv4 → ×1.30 |
| デバフ | なし（1.0） |

```
60 × 1.5 × 1.0 × 1.30 × 1.0 = 117
→ 主ステータス(TECH) +117 / 副ステータス(INT) +59（50%換算・四捨五入。117 × 0.5 = 58.5 → 59）
```

### 例2: 習熟タスク・衰弱デバフ中

| 項目 | 値 |
|---|---|
| 難易度 | D2（基礎値 25） |
| 新規性 | 習熟（0.5） |
| 完遂度 | 0.7 |
| 構造化 | 単一領域のため 1.0 |
| デバフ | 衰弱（0.8） |

```
25 × 0.5 × 0.7 × 1.0 × 0.8 = 7
→ 主ステータス +7 / 副なし
```

### 例3: 証拠なし

```
EXP = 0（他の条件によらず 0。加算処理自体を行わない）
```
