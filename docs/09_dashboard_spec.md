# 09. ダッシュボード仕様（3タブ）

> 正典は `01_requirements.md` FR-8。本書は各パネルの実装仕様（構成・状態・データ源）を定める。
> 配色・タイポ・発光の規約は `11_design_system.md`。
> **チャート実装の前に `dataviz` スキルを読むこと。**

---

## 1. 全体構成

```
┌─────────────────────────────────────────────┐
│  [ ステータス ]  [ ミッション ]  [ 成長推移 ] │  ← タブのみ
├─────────────────────────────────────────────┤
│                                             │
│            （選択中のタブの中身）              │
│                                             │
└─────────────────────────────────────────────┘
```

> **ルール**: **共通ヘッダー・固定の緊急バーは置かない。** タブは完全に独立させる。
> HP・ストリーク・TOTAL Lv は Tab1 のヒーローヘッダーにのみ存在し、他タブには出さない。

| 項目 | 仕様 |
|---|---|
| 実装 | `src/components/tabs.tsx`。**クライアントコンポーネント**（タブ状態のみ持つ） |
| 初期タブ | ステータス |
| a11y | `role="tablist"` / `role="tab"` / `role="tabpanel"`。**左右矢印キーで移動**、`aria-selected` を反映 |
| 非選択タブ | DOM から外す（マウントしない）。カウントダウンの `setInterval` を裏で回さないため |

## 2. Tab 1「ステータス」

構成順序（上から）:

```
1. ヒーローヘッダー
2. 九角形レーダー（中心に《構造化》紋章）
3. ステータス一覧（9件）
4. 歪みメーター（LEARNING vs EXECUTION）
5. 🧬 固有スキルパネル
```

> **注意**: 当初案は「レーダー → 固有スキル → 一覧 → 歪み」だったが、デザイン改善バックログ G
> （`docs/TODO.md`）で「一覧 → 歪み → 固有スキル」の順に変更された。派生の解放条件（例:
> 「TECH Lv70 かつ INT Lv50」）は一覧を読まないと評価できないため、全体 → 内訳 → 解釈 → 次の一手
> の順にする（`07_unique_skill.md` §5.2）。

### 2.1 ヒーローヘッダー — `status/hero-header.tsx`

```
┌─                                                        ─┐
   TOTAL  Lv 32.6   専門職
   ██████████████▁▁▁▁▁▁  次のLvまで 0.4
   🔥 27日        ♥ ████████████▁▁▁▁▁▁  62 / 100
   🔻 衰弱 (残り2日)  ×0.8
└─                                                        ─┘
```

| 要素 | 仕様 |
|---|---|
| TOTAL Lv | 小数第1位まで。**等幅・48px** |
| 総合称号 | `totalTitleFor(floor(totalLv))` |
| EXPバー | TOTAL Lv の小数部を進捗として描画する |
| 🔥ストリーク | 日数。**0 のときは色を落として「途切れています」を併記** |
| ♥HPバー | 残量で色変化（緑 `>50` / 黄 `>25` / 赤 `<=25`）。**赤のときのみ発光** + テキストラベル併記 |
| 🔻デバフ | 成立中のものを**すべてバッジ表示**するが、「**計算に効くのは最も重い1つ**」を明示する |
| 測定期間中 | HPバーを **`—`** にし「ペナルティ免除中」を併記。デバフ表示は**非表示** |

### 2.2 九角形レーダー — `status/status-radar.tsx`

| 項目 | 仕様 |
|---|---|
| ライブラリ | Recharts `RadarChart` |
| 軸 | `STATUS_ORDER` の9軸（`INT → TECH → DATA → MARKETING → PM → BRIDGE → ENGLISH → LEARNING → EXECUTION`） |
| 値 | 各ステータスの**実効Lv**（`min(算出Lv, levelCap)`、Lv1-100）。軸の最大値は**現在の `levelCap`** |
| 主系列 | 現在の実効Lv。Cyan `#22d3ee`、塗り不透明度 0.25 |
| ゴースト系列 | **3ヶ月前**の実効Lv。Violet 半透明 `rgba(139,92,246,0.25)`、破線 |
| 中心 | **《構造化》の紋章**を絶対配置で重ねる（レーダーの中心座標に合わせる） |
| 凡例 | 「現在 / 3ヶ月前」の2件 |
| レスポンシブ | `ResponsiveContainer` で親幅に追従。**固定px幅を持たせない**（375px 必須） |

> **ルール**: 軸の最大値は**現在の levelCap に連動**させる（50 → 70 → 90 → 100）。
> levelCap は全軸共通の単一キャップなので、9軸すべてが同じ最大値を共有する。
> 軸を「現在の各ステータスの最大Lv」に個別自動調整することはしない
> （個別に自動調整すると弱い時期ほど形が大きく見え、成長が分からなくなるため。levelCapという
> 制度上の上限に連動させるのはこれとは別の意図であり矛盾しない）。

**測定期間中**: 未測定の軸（`measured: false`）は値を出さず、ラベルを `???` にする。
測定済みの軸だけで多角形を描くため、**形が徐々に立ち上がっていく**。

### 2.3 固有スキルパネル — `status/unique-skill-panel.tsx`

仕様は `07_unique_skill.md` §5.2。Lv・発動回数・次Lvまでの残回数・倍率・派生5件を表示する。
未解放の派生は**グレーアウトしつつ解放条件と現在値を併記**する（隠さない）。

### 2.4 ステータス一覧 — `status/status-list.tsx`

仕様は `03_status_system.md` §5。`STATUS_ORDER` 順に9件。土台2つの前に区切り線を入れる。

### 2.5 歪みメーター — `status/balance-meter.tsx`

🔥LEARNING と ⚔️EXECUTION の**対比**を1本のバーで表す。

```
🔥 LEARNING  Lv 4                    Lv 3  ⚔️ EXECUTION
   ███████████████████│███████████
   「学びが先行しています。手を動かす量を増やしましょう。」
```

| 状態 | 判定 | 診断文（例） |
|---|---|---|
| 学習過多 | LEARNING − EXECUTION >= 2 | 「知識が実行を追い越しています。手を動かす量を増やしましょう」 |
| 実行過多 | EXECUTION − LEARNING >= 2 | 「手は動いていますが新しい学びが不足しています」 |
| 均衡 | 差が 1 以内 | 「学習と実行のバランスが取れています」 |

> **ルール**: 診断文は `constants.ts` に定義し、コンポーネントに直書きしない。
> 差の閾値（2）も定数化する。

## 3. Tab 2「ミッション」

構成順序（上から）:

```
1. 🚨 緊急ボード（ボス・ゲリラ）
2. 📜 進行中ミッション
3. 🗓 本日のデイリー（5個）
4. 💀 敗北ログ
```

### 3.1 緊急ボード — `mission/urgent-board.tsx`

ボス・ゲリラを**期限が近い順**に並べ、最上部に置く。

| 要素 | 仕様 |
|---|---|
| カウントダウン | `mission/countdown.tsx`。**秒まで動く**（`DD日 HH:MM:SS`）。等幅フォント |
| 更新方式 | **1秒間隔で `Date` の差分を毎回再計算**する。カウンタを自前で減算しない（タブ非表示時のズレを防ぐ・NFR-2） |
| 切迫表示 | **残り3日未満で赤く発光**（パルス）+ テキストラベル併記 |
| 期限切れ | `期限切れ` を表示し、発光を止める（負の値を出さない） |
| reduced-motion | パルスを停止し**静的な赤**にする |
| クリーンアップ | アンマウント時に `clearInterval` する |

### 3.2 進行中ミッション — `mission/mission-list.tsx`

子クエストの進捗バー付き。`完了数 / 全体数` と割合を等幅で表示する。

### 3.3 本日のデイリー — `mission/daily-quests.tsx`

```
┌─ 🗓 本日のデイリー                        🔒 ─┐
   ✓ 技術記事を1本読み、要点を3行で残す   INT  +10
   ✓ コードを30分以上書く                TECH +15
   ・ 英語の技術文書を10分読む            ENG  +8
   ・ 数値を1つ見て気づきを1行残す        DATA +8
   ✓ 今日やることを朝に3つ決める          PM   +5

   ⚠ あと 2 つで 🔥27日 のストリークが途切れます
      未達なら  HP −10 / ⚔️EXECUTION −10 / 🔥 → 0

   🔒 週中はロック中。次に選び直せるのは 月曜日
└─────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|---|---|
| 個数 | **固定5個** |
| 達成表示 | 達成 `✓` / 未達 `・`。**色だけで区別しない** |
| ストリーク警告 | **残り何個で途切れるか**を強調表示。0個なら「本日達成済み」 |
| 損失の事前明示 | 未達時に失う **HP / EXP / ストリーク**を必ず併記する |
| 🔒ロック | 週中は常にロック。**次に選び直せる日（月曜）を明示** |
| Step 1 | 読み取り専用。**チェックの操作はできない**（データ書き込みは Step 3 以降） |

> **ルール**: 「5個すべて達成した日のみストリーク維持」という仕様上、
> **4/5 でも 0 にリセットされる**ことが画面から明確に伝わること（AC-12）。

### 3.4 敗北ログ — `mission/defeat-log.tsx`

種別 / 名称 / 日付 / 被ダメージ（HP・EXPの内訳）/ リベンジ対象 を墓標形式で表示する。
Step 1 ダミーは **2件**（討伐失敗ボス1 + 失敗ミッション1）。

## 4. Tab 3「成長推移」

構成順序（上から）:

```
1. 📈 折れ線グラフ（90日）
2. 🟩 活動ヒートマップ
3. 🤖 GM学習状況
4. 🏛 殿堂
```

### 4.1 折れ線グラフ — `growth/growth-chart.tsx`

| 項目 | 仕様 |
|---|---|
| ライブラリ | Recharts `LineChart` |
| データ | `history.json`（90日分のスナップショット） |
| デフォルト系列 | **3本のみ: TOTAL / 🔥LEARNING / ⚔️EXECUTION** |
| 追加系列 | **凡例クリックで専門7つを個別にオン/オフ**できる |
| 配色 | TOTAL=Cyan / LEARNING=Violet / EXECUTION=Cyan低彩度。専門7つは同一色相帯の明度違い（`11_design_system.md` §3.1） |
| 軸 | Y軸は Lv（`0〜MAX_LEVEL`=100 固定。levelCapには連動させない）。X軸は日付（間引いて表示） |
| ツールチップ | ダーク背景・1px罫線。数値は等幅 |
| レスポンシブ | `ResponsiveContainer`。375px で収まること |

> **ルール**: デフォルトで9本すべてを出さない。**3本に絞る**ことが仕様
> （9本同時だと線が団子になり、最も見たい「学習と実行の乖離」が読めなくなるため）。

### 4.2 活動ヒートマップ — `growth/activity-heatmap.tsx`

| 項目 | 仕様 |
|---|---|
| 実装 | **自前SVG**（ライブラリを足さない） |
| 形式 | GitHub の草。**週 × 曜日**の格子 |
| 期間 | 直近90日 |
| 濃度 | その日の獲得EXP量を4〜5段階に離散化。Cyan の不透明度で表現 |
| 空白 | 活動0の日は最も薄いセル。**ストリークの空白が視覚的に分かること**が目的 |
| a11y | 各セルに `<title>`（日付 + EXP）。色だけに依存しない |
| レスポンシブ | `viewBox` + `width:100%` で親幅に追従。**横スクロールを出さない** |

### 4.3 GM学習状況 — `growth/gm-learning-panel.tsx`

Step 1 は**ダミー値**を表示するのみ（Step 5 で実データ化）。

| 指標 | 内容 |
|---|---|
| 見積精度の推移 | GM の EXP 見積と実績の乖離 |
| D判定一致率 | 難易度判定が本人の感覚と一致した割合 |
| ルーブリック条項数 | 蓄積された査定ルールの数 |

> **注意**: Step 1 ではダミーであることを画面上に明示する（`Step 5 で実データ化` のラベル）。

### 4.4 殿堂 — `growth/hall-of-fame.tsx`

| 状態 | 表示 |
|---|---|
| エントリ0件（1周目） | **「記録なし」**。`generation 1 — 生存中` を併記 |
| 1件以上 | 周回ごとに 最高到達Lv / 称号 / 討伐ボス / 最長ストリーク / 生存日数 / 終焉日 |

> **ルール**: 殿堂は**追記のみ**。GAME OVER 時に既存エントリを消してはならない（`06_penalty.md` §5.2）。

## 5. 測定期間モード（`phase === "calibration"`）

`status.calib.json` を読み込んだときの差分。

| 箇所 | 通常 | 測定期間中 |
|---|---|---|
| 進行バナー | なし | **`CALIBRATION PHASE  Day 6/14   18件中 8件完了`** を各タブ上部に表示（`calibration-banner.tsx`） |
| レーダー | 9軸すべて描画 | 未測定軸は `???`、測定済み軸だけで形を作る |
| HPバー | `62 / 100` | **`—`** +「ペナルティ免除中」 |
| デバフ | 表示 | **非表示** |
| ストリーク | 維持/リセット | 記録のみ（警告文を出さない） |
| 《構造化》紋章 | 通常 | **暗い未解放状態** +「覚醒後に解放」 |
| 歪みメーター | LEARNING/EXECUTION が測定済みなら表示 | **LEARNING/EXECUTION の両方が測定済みになるまで非表示**（`status-tab.tsx`。未測定の軸を
  Lv1扱いで診断すると、同一画面内で `???` 表示と矛盾するため） |

> **注意**: 進行バナーは共通ヘッダーではない。**各タブの内部**に置く
> （「共通ヘッダーを置かない」という原則を崩さないため）。

## 6. データ源のまとめ

| コンポーネント | データ |
|---|---|
| hero-header / status-radar / status-list / balance-meter / unique-skill-panel | `status.json` または `status.calib.json` |
| urgent-board / mission-list / daily-quests / defeat-log | `quests.json` |
| growth-chart / activity-heatmap | `history.json` |
| hall-of-fame | `hall-of-fame.json` |
| gm-learning-panel | ダミー定数（Step 1） |

> **ルール**: JSON の読み込みは**サーバーコンポーネント側**で行い、
> クライアントコンポーネント（タブ・カウントダウン）は props で受け取る。
> `setInterval` を持つのは `countdown.tsx` のみ。
