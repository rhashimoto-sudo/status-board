# エラーログ 2026-08-15

## 1. 正典の食い違いにより、マージ済み定数が退行させられた（HP_COLOR_THRESHOLDS）

**発生箇所**: `src/lib/constants.ts:47`（Wave 5 / Issue #11 / コミット `31b29c8`）

**現象**
dev-phase1-worker が、既に Wave 1〜4 でマージ済みの `HP_COLOR_THRESHOLDS` を
`{ safe: 70, warn: 40 }` → `{ safe: 50, warn: 25 }` に書き戻した。あわせて元のコメント
（「06_penalty.md §7 改訂の経緯」）を削除し、「06 §7 本文は正典と食い違っており未追随」という
逆向きの説明に置き換えていた。

**原因**
ワーカーに渡した Issue 本文（`docs/TODO.md` 由来の受け入れ条件）が、改訂前の値
「`hpZone`: 51→safe/50→warn/26→warn/25→danger/62→safe」のままだった。
ワーカーは受け入れ条件と `02_architecture.md:244,452,659` の2つが一致していることを根拠に、
`06_penalty.md` §7 のほうが古いと**逆に判断**した。

実際の正典関係は逆で、`CLAUDE.md` と `06_penalty.md:142` がともに
「正典は `01_requirements.md` FR-8-1」と宣言しており、FR-8-1（`01_requirements.md:367-371`）は
緑 71〜100 / 黄 41〜70 / 赤 0〜40。`06_penalty.md:152-155` は旧案 `>50/>25/<=25` を
「HP 0 = GAME OVER に対して警告が遅すぎる」として改訂した経緯まで明記し、
「ダミーの HP 62 は黄（警告域）」と結論している。追随漏れだったのは `02_architecture.md` と
`docs/TODO.md` のほうだった。

**対応**
1. 発生元タスクの同じ worktree・同じペインで差し戻させた（`79645f8`）。
   `constants.ts` を `git checkout develop/step1-dashboard --` で復元し、
   `penalty.test.ts` の hpZone 期待値を正典の値
   （71→safe / 70→warn / 41→warn / 40→danger / 62→warn）に更新した
2. `docs/TODO.md` の Issue #11 / #12 の該当チェックリストを正典の値に更新し、
   「旧値であり実装が正しい」旨を明記した（同じ誤判断の再発防止）
3. Wave 6 以降の全ワーカーのプロンプトに「既知の仕様矛盾」節を入れ、
   `HP_COLOR_THRESHOLDS = { safe: 70, warn: 40 }` が正典であること、
   `02_architecture.md` の該当行は採用しないことを明示した
4. `02_architecture.md:244,452,659` の是正は最終の `/spec-sync` で行う

**教訓**
docs 間に食い違いがある状態でワーカーを起動すると、ワーカーは「多数決」で判断してしまい
マージ済みコードを黙って退行させうる。Issue 本文（`docs/TODO.md` の受け入れ条件）は
仕様書の改訂に追随していないことがあるため、**受け入れ条件をそのまま正典として渡さない**。
Wave バリアで `git diff --stat` を宣言と突き合わせる手順（`rules/parallel-worktree.md` 手順7-a）が
この退行の検出点として機能した。

## 2. 宣言外ファイル（docs/TODO.md）の変更

**発生箇所**: Wave 5 / Issue #11 / コミット `31b29c8`

**現象**
ワーカーが対象ファイル宣言（`src/lib/penalty.ts` / `src/test/penalty.test.ts`）に無い
`docs/TODO.md` の「状態」行を書き換えていた。

**原因**
プロンプトに「対象ファイル以外を変更しない」とは書いたが、`docs/TODO.md` が司令塔
（`/logger`）の管理対象であることを明示していなかった。ワーカーは進捗報告のつもりで更新した。

**対応**
差し戻し（`git checkout develop/step1-dashboard -- docs/TODO.md`）のうえ、
Wave 6 以降のプロンプトの禁止事項に「`docs/TODO.md` は司令塔の管理対象なので絶対に触らない」を
明記した。

**教訓**
`rules/parallel-worktree.md` 手順7-a（対象ファイルの実測一致確認）を省略していたら、
TODO.md の状態行が複数タスクのマージで衝突する構図になっていた。並列実行する Wave 6 以降では
特にこの確認を飛ばさない。
