## 00:40:15 — exit code: 0（偽陽性の成功）

**コマンド:** `madge --circular --extensions ts,tsx src/`

**エラー出力:**
```
✔ No circular dependency found!
✖ Skipped 13 files
```

**根本原因:** `--ts-config` を渡さないと madge は tsconfig.json の `paths` エイリアス（`@/*`）を
解決できず、`@/lib/exp`・`@/lib/skill`・`@/lib/data-source` 等を unresolved としてスキップする。
スキップしても終了コード0で成功扱いになるため、依存グラフの過半が欠けた状態で
「循環ゼロ」と報告されていた。`--warning` を付けない限りスキップ件数も表示されない。

**対処:** Codex セカンドレビュー P1 の指摘を裏取りし（修正前 Processed 20 / Skipped 13、
修正後 Processed 26 / Skipped 1）、`--ts-config tsconfig.json` を追加した。

**再発防止:** 「チェックが通った」ではなく「チェックが対象を実際に見ているか」を確認する。
静的解析ツールを導入するときは、処理件数・スキップ件数を一度は目視し、
プロジェクトのファイル数と整合するか照合してから受け入れ条件を満たしたと判断する。

## 00:52:10 — exit code: 2（フックによるブロック / 誤検知）

**コマンド:** `printf ... > /tmp/codex-review-w4.env` を含む複合コマンド

**エラー出力:**
```
PreToolUse:Bash hook error: [bash ~/.claude/vibe-coding/hooks/pre-bash.sh]
```

**根本原因:** `pre-bash.sh` の `.env` リーク防止パターン
`(cat|head|tail|less|more|echo.*\$).*\.env` が、`.env` という**拡張子で終わる一時ファイルへの
書き込み**にも一致した。パターンは「`.env` の内容を表示する」ことを狙っているが、
`echo "$VAR" > 何か.env` のような書き込み方向のリダイレクトも巻き込む。
機密情報とは無関係な作業ファイルだった。

**対処:** 一時ファイル名を `/tmp/codex-review-w4-run.txt` に変更して再実行した。
フック自体は変更していない（誤検知だが安全側に倒す設計として妥当なため）。

**再発防止:** 一時ファイルに `.env` で終わる名前を使わない。

## 00:44:30 — exit code: 0（早期 idle / 出力未生成）

**コマンド:** `herdr agent wait codex-review-wave4-w4-31062 --status idle --timeout 600000`

**エラー出力:**
```
（idle を返すが -o の出力ファイル result.md が存在しない状態が30秒継続）
```

**根本原因:** `codex-second-review` スキルが警告しているとおり、herdr の `--status idle` は
実処理の完了より早く返ることがある。実際には codex プロセス（PID 31070）がまだ動いており、
出力ファイルは約90秒後に生成された。

**対処:** スキル手順どおり `ls` で出力ファイルの実在を確認し、無い間は `pgrep` で
codex プロセスの生存を確認しながらポーリングした。プロセス終了かつ出力なしを
失敗条件、出力生成を成功条件として待機した。

**再発防止:** `herdr agent wait` の idle を完了条件として単独で信頼しない。
`-o` の出力ファイルの実在と対象プロセスの生存の両方を見て完了判定する
（スキルに既に明記されている手順を省略しない）。
