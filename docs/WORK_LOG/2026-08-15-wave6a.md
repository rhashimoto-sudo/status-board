## Wave 5 バリア追補: `applyPenalty` のクランプ契約を確定（Issue #11-nextHp）

Wave 5 バリアで未決だった「`applyPenalty` が `hpDelta` / `expDeltas` を未クランプ・未フロアで返す
契約をどう扱うか」について、**ユーザー判断で「`PenaltyResult` にクランプ済み `nextHp` を追加する」に
確定**した。呼び出し側が `state.hp + hpDelta` を素で計算して安全装置 S-2（HP は常に 0〜100、
`06_penalty.md` §4）に違反する経路を型で塞ぐのが目的。

### src/lib/types.ts
**操作**: 修正
`PenaltyResult` に `nextHp: number` を追加し、3フィールドに役割分担のドキュメントコメントを付けた。

- `hpDelta`: このペナルティによる HP の増減量（表示用）。**クランプされていない生の delta**
- `nextHp`: 適用後の確定 HP。`clampHp` 適用済みで常に 0〜100（**S-2 を型の側で保証する**）
- `expDeltas`: EXP の生の増減量。**S-1（EXPフロア）は適用されていない。消費側は必ず
  `src/lib/exp.ts` の `applyExpDelta` を通すこと**

`hpDelta` は「このペナルティで何点失ったか」の表示に必要なため残した。

### src/lib/penalty.ts
**操作**: 修正
4種すべての戻り値に `nextHp` を追加した。

**`NO_PENALTY` のモジュールスコープ定数は廃止した。** `state.hp` を知らないと `nextHp` を返せないため、
`applyPenalty` 内のインライン return に変更し、免除中も `hpDelta: 0` / `nextHp: clampHp(state.hp)` を
返すようにした（免除中でも「現在の HP」が正しく返る）。
**S-4 の免除判定は `if (state.phase === "calibration")` の入口1箇所のまま**で、C-9 を壊していない。

`gameOver` フラグは `isGameOver(clampHp(state.hp + hpDelta))` から `isGameOver(nextHp)` に統一した。
同じ値の二重計算がなくなり、`gameOver` と `nextHp` が構造的に必ず一貫する。

### src/test/penalty.test.ts
**操作**: 修正
`nextHp` の境界テストを追加（HP 5 + `dailyMiss`(−10) → `nextHp: 0` かつ `hpDelta: -10` の両立、
HP 98 からの回復側境界、HP 100 + `bossFailed`(−50) → `nextHp: 50`、
calibration 時の全4種で `nextHp === clampHp(state.hp)`、全4種で `gameOver === isGameOver(nextHp)` の一貫性）。
