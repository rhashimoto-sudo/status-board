## 実測で見つかった注意点（今回は修正しない・記録のみ）

### 1. Recharts の `ResponsiveContainer` がリサイズに追従しない

**新規ロード時は各幅で正しく描画される**（320→288 / 375→343 / 768→736）が、
**読み込み後に幅を変えても折れ線の SVG 幅が初期値のまま**だった（375 で読み込み後、
768 にしても 320 にしても 343px のまま。2.5秒待機 + `resize` イベント送出でも変化なし）。

- 実装は `ResponsiveContainer width="100%" height={240}` で**固定px幅を持たせておらず、
  仕様どおり**（AC-13 / C-20 を満たす）
- AC-13 の検証点（375 / 768 / 1024 / 1440）では、チャートがビューポートより狭いままなので
  `scrollWidth <= clientWidth` は**成立する**（違反ではない）
- ただし 320px に縮めた場合のみ `scrollWidth` 359 > `clientWidth` 320 になる。**320px は
  AC-13 の検証対象外**（Issue #24 は 375 / 768 / 1024 / 1440 を指定）
- **外側から iframe をリサイズした際の ResizeObserver の挙動という計測手法側の要因の可能性もある。**
  Wave 9（Issue #24）の最終監査は実ブラウザの DevTools で行うため、そこで再確認すること

### 2. ヒートマップの `intensity` は呼び出し側が算出する契約

`ActivityHeatmap({ days: { date, gainedExp, intensity }[] })` は `intensity` を props で受け取る。
**`HEATMAP_INTENSITY_STEPS`（5段階）へのマッピングは呼び出し側の責務**であり、
**Wave 7 の Issue #22（`growth-tab.tsx`）で実装する必要がある。**
司令塔の一時確認ページでは暫定に `Math.ceil` で算出したため、目視では大半のセルが最大濃度に
寄っていた（**確認ページ側の都合であり、コンポーネントの不具合ではない**）。
Wave 7 で階調が意味を持つマッピングを実装すること。
