## 真因（司令塔が 375px の iframe で再現・二分探索して特定）

| 祖先コンテナ | `document.documentElement.scrollWidth` |
|---|---|
| `display:flex; flex-direction:column` | **375**（問題が出ない） |
| **`display:grid; grid-template-columns:1fr`** | **391（再現）** |
| `display:grid; grid-template-columns:minmax(0,1fr)` | 375 |
| `display:block` | 375 |

**grid アイテムは `min-width` の既定値が `auto` のため、パネルが min-content 未満に縮めない。**
そして緊急ボードのゲリラ行の min-content が大きいままだった。

grid コンテナ下で実測した min-content の内訳:

```
panel(.panel-surface)   min-content 375px
 └ li.flex.flex-wrap    min-content 341px
     └ div.flex.min-w-0 min-content 341px   ← ここが縮まない
         ├ span(⚡)
         ├ span.min-w-0.flex-1.truncate     ← min-w-0 は効いているが min-content 寄与が消えない
         └ span(ゲリラ（D3）)
```

**`min-width: 0` はレイアウト時に縮むことを許可するが、flex コンテナの min-content 寄与を
0 にしきれない。** そのため祖先が「min-content 未満に縮めない」文脈（grid アイテム）に
置かれた瞬間に破綻する。

Wave 7（Issue #21 `mission-tab.tsx`）と Wave 8（Issue #23 `dashboard.tsx`）で実際のコンテナが
入るため、**そこで grid が使われれば再発する**。コンテナの実装に依存しない形に直す必要があった。

## 修正（2箇所）

### 1. `src/components/mission/urgent-board.tsx` — 内側 `div` を 3列 grid に

```diff
-<div className="flex min-w-0 items-center gap-2">
+<div className="grid grid-cols-[auto_minmax(0,1fr)_auto] items-center gap-2">
   <span aria-hidden="true">{entry.kind === "boss" ? "👹" : "⚡"}</span>
-  <span className="min-w-0 flex-1 truncate">{entry.quest.title}</span>
+  <span className="min-w-0 truncate">{entry.quest.title}</span>
   <span className="text-[color:var(--color-text-secondary)]">…</span>
 </div>
```

`minmax(0,1fr)` により**トラックの最小幅が 0 になり、min-content 寄与が構造的に消える**。
アイコン列とメタ列は `auto` で内容幅を保つ。

**外側の `li`（`flex flex-wrap`）は変更していない。** カウントダウンが狭い幅で次の行に
折り返す挙動を保つため（実測でも行の高さは 56px のまま）。

### 2. `src/components/ui/panel.tsx` — `min-w-0` を追加（systemic な防御）

```diff
-className={`panel-surface relative rounded p-4 md:p-6 ${className ?? ""}`}
+className={`panel-surface relative min-w-0 rounded p-4 md:p-6 ${className ?? ""}`}
```

**Panel が grid / flex のどちらのアイテムになっても min-content 未満に縮める**ようになり、
同種の問題が他のパネルで再発しなくなる。実測ではこの1クラスだけでも 391 → 375 になった。
見た目は変わらない。

## 教訓（前回の教訓を更新する）

1. **「ブラウザで実測した」だけでは不十分。問題が再現する条件で測らなければ意味がない。**
   前回は問題の出ない `flex` コンテナで測って「375、はみ出し0件」と報告してしまった。
   修正を検証するときは、**まず修正前のコードで問題を再現させ**、
   その同じ条件で修正後に解消することを確認する
2. **確認ページは製品の構造に合わせ、タブごとに分離する。** 複数タブの部品を1ページに混ぜると、
   製品では起こらない現象（トラック幅の共有など）を追うことになる
3. **`min-width: 0` は「縮むことを許可する」だけで、min-content 寄与を 0 にはしない。**
   祖先が grid アイテムのように「min-content 未満に縮めない」文脈だと破綻する。
   確実に潰すには **grid の `minmax(0,1fr)` でトラック最小幅を 0 にする**のが構造的
4. レイアウト（CSS）の受け入れ条件は `npm run verify` を**完全に素通りする**。
   AC-13 は Wave 9 の最終監査でも実ブラウザで測ること
