## レビュー指摘5件の修正（Issue #lotB-fix）

5件のうち3件が `daily-quests.tsx` に集中するため並列化せず逐次1件で実行した。

### A. 曜日がランタイムのタイムゾーンで計算されていた【最優先・本番でのみ壊れる】

`weekdayLabel` が `new Date(iso).getDay()` を使っており、**ランタイムのローカル TZ** で曜日が決まっていた。

```
TZ=Asia/Tokyo  →  new Date("2026-08-17T00:00:00+09:00").getDay() = 1（月）
TZ=UTC         →  同じ入力で getDay() = 0（日）   ← Vercel の Node ランタイム
```

`DailyQuests` はサーバーコンポーネントで **Vercel の Node ランタイムは UTC** のため、
`lockedUntil` が JST 00:00 のデータだと本番では常に**前日の曜日**が出る。
ローカルの JST 環境では正しく見えるため、**デプロイして初めて壊れる**種類のバグ。

#### 司令塔がタイムゾーンを確定した（docs から導出できなかったため）

`docs/10_notion_schema.md:64` は「スナップショットの取得時刻・タイムゾーン | **未確定**」としており、
**docs にタイムゾーンの正典が無い**。そこで司令塔が次を確定し、worker に指示した:

- **表示タイムゾーンは `Asia/Tokyo` に固定する。** 根拠: 本プロジェクトは日本語の個人用
  ダッシュボードであり（`CLAUDE.md` / `layout.tsx` の `html lang="ja"`）、
  ローカル開発（JST）と Vercel（UTC）で表示が変わらないことが要件（AC-10 の
  「再起動・環境変数設定が不要」と同じ思想）
- **識別子は `constants.ts` に定数として置く**（`CLAUDE.md` の「調整値は constants.ts に一元管理」）

→ `src/lib/constants.ts` に `DISPLAY_TIME_ZONE = "Asia/Tokyo"` を追加。
**この決定の docs への反映は `/spec-sync` の対象。**

#### 共通化: `src/lib/datetime.ts` を新設

**新規ファイル**。`Intl.DateTimeFormat` に `timeZone` を明示する2関数を提供する。

- `weekdayIndexInTimeZone(date, timeZone = DISPLAY_TIME_ZONE)` — `en-US` の `weekday: "short"` を
  `["Sun".."Sat"]` に照合して 0〜6 を返す
- `dateKeyInTimeZone(date, timeZone = DISPLAY_TIME_ZONE)` — `en-CA` ロケールが `YYYY-MM-DD` を
  返す仕様を使う

**`penalty.ts` の `localDateString` は削除し、`dateKeyInTimeZone` に統合した。**
`localDateString` は `getFullYear`/`getMonth`/`getDate` を使っており**同じ TZ 依存の問題**を
抱えていた（Wave 5 で `toISOString` の UTC 問題を直した際の修正が不十分だった）。
`gameOver` の `endedAt` もこれで JST 固定になる。

**循環依存なし**: `datetime.ts` は `constants.ts` のみを import し、`constants.ts` は何も import しない。
`penalty.ts` → `datetime.ts` → `constants.ts` の一方向。`npm run check:cycles` で0件を確認済み。

#### テスト（`src/test/datetime.test.ts`・新規）

`it.each(["UTC", "Asia/Tokyo"])` で **`process.env.TZ` を切り替えても同じ曜日・同じ日付文字列を返す**ことを
固定した。`afterEach` で `process.env.TZ` を元に戻し、他のテストに影響させない。

### B. 空配列で「✓ 本日達成済み」と表示される

`remaining === 0` の判定より前に `dailies.length === 0` の分岐を入れ、
「本日のデイリーはありません」を出すようにした。

### C. 解釈不能な deadline で `NaN日 NaN:NaN:NaN` が出る

`Number.isNaN(remainingMs)` でガードし、マウント前と同じ `--日 --:--:--` の
プレースホルダーにフォールバックする（**発光もしない**）。

### D. 敗北ログの符号規約が不一致

ダミーデータは `hpDamage` が正（50）、`expDamage[].amount` が負（-90）で不統一だった。
**データ側の符号は矯正せず、表示側が両方とも `-Math.abs(...)` で正規化する契約**に決め、
`src/lib/types.ts` の `DefeatEntry` に型コメントとして明記した。
これにより将来どちらの符号でデータが来ても表示は必ず「-数値」になり、
`expDamage` が正の値で「増加」に見えることはない。

### E. ロック通知が経過判定をしていない

`nextSelectableLabel(dailies, nowMs)` を切り出し、
**`lockedUntil` の最大値**（最も遅く解除される日時）を取り、**現在時刻を過ぎていれば表示しない**ようにした。
`dailies[0]` のみを読み5件が同じ値を持つ前提を置く実装をやめた。
