- **Issue #28 `src/lib/level.ts`**（コミット `700b50a`）: levelCap（実効Lv）を導入。
  `levelFromExp(exp, levelCap = MAX_LEVEL)` / `levelsOf(statuses, levelCap)` /
  `computeTotalLevel(statuses, levelCap)` / `weakestStatuses(statuses, levelCap, count = WEAK_AXIS_COUNT)`。
  内部に `clampLevelCap`（1..MAX_LEVEL）を追加。
  - **cap API 形状の判断（呼び出し元8箇所を実測して決定）**: `levelFromExp` の cap は
    **任意引数・既定 `MAX_LEVEL`**。理由は `exp.ts:48,53` の EXP 減点フロア計算
    （`Math.max(newExp, levelFloorExp(currentLevel))`）が**生のLv**を必要とし、キャップ後のLvで
    フロアすると貯蓄が消えるうえ、`exp.ts` は Issue #28 の変更禁止対象だったため。既定値
    `MAX_LEVEL` はキャップなしと数学的に等価（no-op）。一方、集計系3関数
    （`levelsOf`/`computeTotalLevel`/`weakestStatuses`）は渡し忘れると全軸の上限が無言で
    効かなくなるため**必須引数**にした。
  - `expToNextLevel`/`levelProgress`/`levelFloorExp` は**意図的に cap 引数を持たせない**。
    生の累積EXPに対する値を返し続けることが、S-2 の「キャップ到達中も貯まっているEXP量を見せる」
    画面要件を満たす唯一の形（0/null に潰さない）。
  - 実測: `levelFromExp(0)=1` / `(8)=2` / `(7)=1` / `(11287)=91` / `(17318)=100` / `(999999)=100` /
    `(11287, 50)=50` / `(11287, 70)=70`。`levelProgress(11287)=0`（Lv91のちょうど下限）・
    `expToNextLevel(11287)=551` と cap に無関係な生の値を返す。
