### `/code-review` の指摘と対応

ユーザー判断により、以下のように振り分けた。

**今回修正する（`develop/step1-dashboard-issue-11-fix` で実施）**

1. `gameOver` のリセット取りこぼし — `{ ...state.statuses[key], exp: 0 }` としているため
   `expThreeMonthsAgo` / `measured` が前世代の値のまま残る。レーダーの3ヶ月前ゴースト（FR-8-1 #2）が
   消えた世代の形を描き続け、新世代が退行して見える。`06_penalty.md` §5.1 の「全9ステータスを初期化」に反する
2. `endedAt` が UTC 日付 — `new Date().toISOString().slice(0,10)` は UTC 日を取るため、
   JST 深夜の GAME OVER が前日として記録される。`Snapshot.date` 等はローカル日前提で不整合
3. `updateStreak` の件数判定 — `dailies.length !== DAILY_QUEST_COUNT` で無条件に0を返すため、
   データ不整合（空配列・件数ずれ）と「デイリー未達」が区別できず、全達成でもストリークが消える
4. `docs/TODO.md` Issue #11 / #12 の古い hpZone 閾値（司令塔が実施）

**Step 3 送り（ユーザー判断）** — `docs/TODO.md` のスコープ外セクションに追記した

- `gameOver` の `titles` / `defeatedBosses` / `survivedDays` / `longestStreak` のハードコード。
  原因は `GameState`（`types.ts:89-94`）に元データを保持するフィールドが無いことで、
  Issue #11 の範囲では埋めようがない

  `PenaltyKind`（`types.ts:51`）が4種で「デイリー3日連続未達」を表現できない
