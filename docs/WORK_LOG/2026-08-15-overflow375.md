## 現象（team-lead がブラウザで実測して検出）

375px ビューポートで `document.documentElement.scrollWidth` が **391px**
（`clientWidth` 375 を **16px 超過**）。`CLAUDE.md` の「375px で横スクロールを発生させない」と
受け入れ条件 AC-13 に違反していた。

**`npm run verify` は通っていた。** CSS のレイアウト問題は typecheck とテストでは
一切検出できないため、ブラウザ実測でしか見つからない種類の不具合だった。

## 原因

`src/components/mission/urgent-board.tsx` のゲリラ行:

```
li.flex.flex-wrap...              min-content 341px
 └ div.flex.min-w-0...            min-content 341px   ← 親には min-w-0 がある
     └ span.truncate              min-content 256px   ← ここが縮まない
        white-space: nowrap
```

`truncate` は `white-space: nowrap` を含むため、**flex アイテムである `span` 自身に `min-w-0` が
無いと min-content 以下に縮まない**（flex アイテムの `min-width` 初期値が `auto` のため）。
親の `div`（`:40`）には `min-w-0` が付いているのに、子の `span`（`:42`）に付いていないという抜け。

ゲリラのタイトル「取引先からの緊急仕様確認への対応」が 256px を要求
→ パネルの min-content が膨張 → `p-4`（左右 16px）+ ボーダー 1px×2 を加えて **391px** になっていた。

**ボス行は min-content 238px で閾値を超えないため発生しなかった。タイトルが長い行でだけ起きる。**
ダミーデータのタイトルがもう少し短ければ Wave 9 の最終監査まで気づかなかった種類の問題。

## 修正

`urgent-board.tsx:42` の1行のみ:

```diff
-<span className="truncate">{entry.quest.title}</span>
+<span className="min-w-0 flex-1 truncate">{entry.quest.title}</span>
```

`min-w-0` で min-content 制約を外し、`flex-1` で残り幅を取らせる。

## 教訓

- **レイアウト（CSS）の受け入れ条件は `npm run verify` では検証できない。**
  AC-13（375px で横スクロールなし）のような条件は、実際に描画して
  `scrollWidth <= clientWidth` を数値で確認するまで「通った」と言えない
- flex の入れ子で `truncate` / `whitespace-nowrap` を使う場合、
  **親だけでなく当該要素自身にも `min-w-0` が必要**。
  親に付けたことで対処済みと錯覚しやすい
- この種の不具合は**データ依存で顕在化する**（長いタイトルの行でだけ出る）。
  ダミーデータを短くすると隠れてしまうため、境界に近い長さのデータを保っておく価値がある
