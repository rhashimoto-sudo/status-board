## A. 専門7系列が既定2系列と判別できない【最優先】

**現象**（team-lead が全10系列を表示して `stroke` を実測）: `specialtyColor()` が
「8分割の内側7点（12.5%〜87.5%）」を採っていたため、両端との差が **12.5ポイントしかなく**、
INT が TOTAL と、ENGLISH が LEARNING とほぼ同色になっていた。
既定系列との違いは線幅 2px vs 1.5px のみで視覚的に区別できなかった。

**修正**: 帯を **25%〜75%** に狭め、その中に7点を均等配置した。

```
ratio = 25 + (index / (SPECIALTIES.length - 1)) * (75 - 25)
```

## D. `role="img"` が各セルの `<title>` を隠していた【a11y】

`<svg role="img">` は**配下をアクセシビリティツリーから刈る**ため、各セルの `<title>`（日付+EXP）が
スクリーンリーダーに一切届いていなかった。`docs/09_dashboard_spec.md` §4.2 は
各セルの `<title>` を**色に依存しない情報伝達手段として明示的に要求**している（NFR-4/NFR-6）。

**修正**: svg を `role="group"`（概要のみ）に変え、**各 `<rect>` に `role="img"` + 個別 `aria-label`**を
付与した。`<title>` はポインタ操作時のネイティブツールチップ用に残している。

## E. 凡例チップが実際のセルと違う描画

セルは `fillOpacity`（**枠線は不透明のまま**）なのに、凡例チップは要素全体の `opacity` を使っており、
最小段階のチップが**枠線ごと 0.06 まで薄くなり背景に対してほぼ不可視**だった。

**修正**: チップを `backgroundColor: color-mix(in srgb, var(--color-accent-cyan) N%, transparent)` にし、
**枠線は `border` の不透明色のまま**維持した。`N` はセル側の `fillOpacity` と同じ割合。

**司令塔が目視で確認**: 375px で「少ない → 多い」の**5段階すべてのチップが視認でき、
最小段階も枠線が見える**（拡大スクリーンショットで確認）。

## F. タイムゾーン解釈が偶然で成立していた

`weekdayIndexInTimeZone(new Date(`${date}T00:00:00Z`), DISPLAY_TIME_ZONE)` は、
`YYYY-MM-DD`（**すでに `DISPLAY_TIME_ZONE` 基準で確定済み**）を UTC 解釈してから
`DISPLAY_TIME_ZONE` で**再評価**していた。**Asia/Tokyo が UTC+9 だから同じ日になるだけ**で、
負のオフセットの地域に変えると**全セルが1行ずれ、日〜土のグリッドが黙って崩れる**。

**修正**: 第2引数を **`"UTC"`** に変更（`T00:00:00Z` と対応させる）。

### 再発防止: `src/lib/datetime.ts` にドキュメントコメントを追加

**タイムゾーン関連の不具合は今回で3件目**（`penalty.ts` の `endedAt` / `daily-quests.tsx` の曜日 / 本件）。

## G. `SPECIALTY_ORDER as readonly SpecialtyStatusKey[]` の無検査アサーション

`SPECIALTY_ORDER` は `STATUS_ORDER.slice(0, 7)` で型上 `StatusKey[]`。無検査アサーションのため、
`STATUS_ORDER` の並びが変わって `LEARNING`/`EXECUTION` が先頭7つに入っても**型エラーが出ず**、
凡例が既定系列と重複した線を描き専門が1つ落ちる状態だった。

**修正**: `constants.ts` を変更せず、**`growth-chart.tsx` 側に実行時の型ガード**を置いた。

```ts
function isSpecialtyKey(key: StatusKey): key is SpecialtyStatusKey {
  return !(FOUNDATION_ORDER as readonly StatusKey[]).includes(key);
}
const SPECIALTIES: readonly SpecialtyStatusKey[] = SPECIALTY_ORDER.filter(isSpecialtyKey);
```

`FOUNDATION_ORDER`（LEARNING/EXECUTION）を実行時に除外するため、並びが変わっても
土台2つが専門系列として二重描画されない。`grep -rn "as readonly SpecialtyStatusKey" src/` は **0件**。
